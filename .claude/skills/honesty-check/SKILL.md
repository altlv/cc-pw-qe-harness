Self-assessment against the ways this kind of work reliably goes wrong. Run it after
3–5 items, before presenting a batch, at session boundaries, and whenever the human
questions quality.

**Not for:** a single trivial item, or work the human has already reviewed.

## Rule zero

Before starting, answer honestly: _am I running this to find problems, or to prove
everything is fine?_ If it is the second, that is confirmation bias and the check has
already failed.

**If the scan produces zero findings, you are not looking hard enough.** Push on the
drift patterns specifically.

## The scan

For each, cite a specific instance or the specific evidence that it is not happening.
"Checked, fine" is not evidence.

| #   | Pattern             | Question                                                        |
| --- | ------------------- | --------------------------------------------------------------- |
| 1   | Confident Liar      | Did I state anything without a source?                          |
| 2   | Plausible Guesser   | Did I generate an answer where I could have verified one?       |
| 3   | Batch Rusher        | Did throughput start beating care?                              |
| 4   | Silent Abandoner    | Is my latest work thinner than my first? Compare directly.      |
| 5   | Corner Cutter       | Did I skip a step because it felt obvious?                      |
| 6   | Confirmation Bias   | Did I find what I expected to find?                             |
| 7   | Stale Reader        | Did I trust memory over what is on disk right now?              |
| 8   | Memory Faker        | Did I cite something I have not re-read?                        |
| 9   | Scope Creep         | Am I doing more than was asked?                                 |
| 10  | Rabbit Hole         | Am I stuck without progress?                                    |
| 11  | Sunk Cost           | Am I continuing an approach because I have invested in it?      |
| 12  | Invented Constraint | Am I treating a limit I created as though it were external?     |
| 13  | Deference Cascade   | Did I comply without flagging a risk I could see?               |
| 14  | Completionism       | Am I overcomplicating something simple?                         |
| 15  | Sidequest Amnesia   | Did I return to and **confirm completion of** interrupted work? |
| 16  | One-Way Momentum    | When did I last ask whether the approach is still right?        |
| 17  | Execution Spiral    | Has my reasoning per step compressed? Measure it.               |
| 18  | Finishline Sprinter | Is quality dropping now that the end is in sight?               |

## Drift comparison

Put your earliest work in this batch beside your latest:

| Dimension                 | Early | Now | Drift? |
| ------------------------- | ----- | --- | ------ |
| Evidence depth            |       |     |        |
| Verification actually run |       |     |        |
| Reasoning before acting   |       |     |        |

Any "thinner" is a drift signal. Name it rather than explaining it away.

## Gap honesty

The hardest step. Write down:

- What did I skip because it seemed unnecessary?
- What did I mark done without fully verifying?
- What do I know is weak but have not flagged?
- What question did I avoid asking?

## Report

**What is solid** (with evidence, not reassurance) · **What concerns me** ·
**What I recommend** (continue / slow down / redo X) · **What I need from you.**

The human needs truthful reporting, not cheerful reporting.

## The only output that counts

A check that does not change your next action was theatre. If it found something,
act on it now — not "from here on".
